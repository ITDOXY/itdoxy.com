# Шаблоны досье статьи

Для конкретной статьи скопируйте шесть файлов из этой папки в `research/<article-id>/`. Саму инструкцию копировать не нужно. Шаблоны не содержат реальных источников, проверок или утверждений редактора.

Используйте один стабильный `article-id` во всех файлах. Он не зависит от заголовка, slug, пути статьи, генератора или темы. При повторной работе обновляйте существующее досье, а не создавайте дубликат.

| Файл | Когда заполнять |
|---|---|
| `brief.md` | До исследования: задача, границы и исходная версия |
| `sources.yaml` | По мере чтения: реестр и точные места в источниках |
| `findings.md` | До плана и при уточнении выводов: тезисы и доказательства |
| `outline.md` | До написания или изменения статьи: план и запись об утверждении |
| `verification.md` | При подготовке и выполнении проверок: критерии, среда, результаты |
| `review.md` | После проверок и перед отправкой: замечания и решения по каждой стадии |

Для нового досье используйте `provenance: new`. При восстановлении досье старой статьи установите `provenance: reconstructed` и запишите дату восстановления. В реестре разделяйте источники из старой статьи и найденные сейчас. В `findings.md` различайте историческую применимость и текущее состояние. Заполнители в угловых скобках заменяйте фактическими сведениями; неизвестное отмечайте явно.

В `research/` переносите только материалы, подготовленные для публичного доступа. Приватные исходники храните вне репозитория. Для неконфиденциальных временных материалов предусмотрен игнорируемый `/work/editorial/`. Игнорирование не удаляет отслеживаемые файлы и не очищает историю.

Правила: [исследование](../research-policy.md), [согласования](../editorial-workflow.md), [качество и публичность](../article-quality.md), [проверки](../editorial-testing.md).
